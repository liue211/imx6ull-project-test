# 联网指南 — 开发板通过电脑 WiFi 共享上网(ICS)

> 场景:笔记本(WiFi 上网)与开发板通过网线直连,开启 Windows 网络共享(ICS/NAT),让板子访问外网
> 用途:MQTT 上云(升级计划 功能组二)、OTA 下载(功能组三)、远程调试
> 前提:电脑 WiFi 能正常上网;电脑有以太网口(本机为 Realtek PCIe GbE);网线一根

## 网络拓扑

```
[开发板 i.MX6ULL] ──网线── [笔记本 Realtek 网口]   [笔记本 WiFi] ── 路由器 192.168.31.1 ── 互联网
   eth0: 192.168.137.x        (ICS 固定: 192.168.137.1)
```

关键点:Windows 的"网络共享(ICS)"会把**被共享的那个以太网口**固定配置为 `192.168.137.1` 网段,并自动开启 DHCP 服务(派发 192.168.137.2~254),同时做 NAT 转发和 DNS 转发。**电脑侧不需要手动配 IP,ICS 自动完成。**

---

## 第一步:电脑侧配置(Windows 10/11)

1. 网线一头插开发板网口,另一头插电脑以太网口(插好后 `ipconfig` 里"以太网"适配器从 Not Present 变为已连接)。
2. `Win + R` → 输入 `ncpa.cpl` 回车,打开网络连接窗口。
3. 找到 **WLAN 2**(Intel AX210 WiFi)适配器 → 右键 → **属性** → 切到 **"共享"选项卡**。
4. 勾选 **"允许其他网络用户通过此计算机的 Internet 连接来连接"**,下面的下拉框选择 **"以太网"** → 确定。
5. 弹窗提示"将使用 192.168.137.1 作为连接设备的 IP 地址",点确定。
6. 验证:双击"以太网"适配器,状态显示"已连接",IP 为 `192.168.137.1`。

注意事项:

- 若"共享"选项卡勾选时报错:检查以太网适配器是否处于启用状态;检查服务 `SharedAccess`(Internet Connection Sharing)是否运行(`Win+R` → `services.msc` → 找到并启动)。
- Windows 防火墙不用改:ICS 默认放行 NAT 转发;板子 ping 电脑(192.168.137.1)可能被防火墙拦,属正常现象,不影响板子上外网。
- 电脑网口此前若手动配过静态 IP,勾选共享后会被 ICS 覆盖为 192.168.137.1,属正常。

## 第二步:板子侧配置(串口终端登录 root)

### 0. 确认插的是哪个网口、对应哪个 eth

正点原子 ALPHA 板有两个网口(ENET1/ENET2),先确认:

```sh
ifconfig -a | grep -E "^eth"      # 看有哪些网口
dmesg | grep -i fec               # 看 fec 网卡驱动是否加载
```

ENET1 通常对应 eth0,ENET2 对应 eth1,以实际为准;下面的 `eth0` 按实际网口名替换。

### 方式 A:DHCP 自动获取(推荐,ICS 自带 DHCP)

```sh
udhcpc -i eth0
ifconfig eth0                     # 应显示 inet 192.168.137.x
```

### 方式 B:静态 IP(ICS DHCP 异常时)

```sh
ifconfig eth0 192.168.137.20 netmask 255.255.255.0
route add default gw 192.168.137.1
echo "nameserver 192.168.137.1" > /etc/resolv.conf   # ICS 做 DNS 转发
```

## 第三步:验证(按顺序,逐条确认)

```sh
ping -c 3 192.168.137.1    # ① 通 = 网线/链路正常(被防火墙拦属正常,看②③)
ping -c 3 223.5.5.5        # ② 通 = ICS NAT 转发正常(外网 IP)
ping -c 3 www.baidu.com    # ③ 通 = DNS 正常
```

- ② 通、③ 不通 → DNS 问题,检查 `/etc/resolv.conf`(可换 `nameserver 223.5.5.5`)。
- ① 都不通 → 看网口指示灯、`dmesg | grep -i fec`、电脑侧"以太网"是否 192.168.137.1。

## 第四步:开机自动配置(持久化)

- **若 rootfs 有 ifupdown**(存在 `/etc/network/interfaces`):追加

```
auto eth0
iface eth0 inet dhcp
```

- **busybox 精简 rootfs(正点原子默认)**:在 `/etc/init.d/rcS`(或 rc.local)末尾追加

```sh
udhcpc -i eth0 &
```

## 常见问题

| 现象 | 排查 |
|---|---|
| 板子 ping 不通 192.168.137.1 | 网线/指示灯;电脑"以太网"是否 192.168.137.1;`dmesg \| grep -i fec` 驱动是否加载 |
| 共享选项卡勾选失败/报错 | 以太网适配器被禁用;`SharedAccess` 服务未运行 |
| 板子能 ping IP、不能 ping 域名 | `/etc/resolv.conf` 错误;ICS DNS 转发异常可换 `nameserver 223.5.5.5` |
| 开共享后电脑 WiFi 掉线 | 个别 WiFi 驱动与 ICS 兼容差,更新 WiFi 驱动后再试 |
| 板子拿到 192.168.137.x 但外网慢 | ICS 走电脑转发,延迟较高;大流量(OTA 大包)建议改插路由器 |

## 与项目的关系

- **MQTT 上云(升级计划 功能组二)**:网络通了之后,把 `mqtt_client.cpp` 里的 broker 地址从 `127.0.0.1:1883` 改为公网 broker(如 `test.mosquitto.org:1883` 或自建服务器),即可从板子上报传感器数据到云端看板。
- **OTA(功能组三)**:板子可直接从 HTTP 服务器下载升级包;大包建议直连路由器以获得稳定带宽。

## 附录:有路由器时的更简方案

如果板子能拉一根网线到路由器(本机路由器为小米 192.168.31.1),**比 ICS 更简单稳定**:板子网线插路由器 LAN 口 → `udhcpc -i eth0` 自动获取 `192.168.31.x` → 直接上外网,不需要电脑做共享。ICS 方案只用于"必须直连电脑、没有路由器可用"的场景。

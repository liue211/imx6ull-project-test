# 面试准备文档 — imx6ull 嵌入式 Qt 项目

> 项目:基于正点原子 i.MX6ULL 开发板的嵌入式 Linux Qt 模块化项目
> 用途:面试前 1~2 天快速过一遍,重点是"每个模块一行原理 + 高频题回答要点 + 一个踩坑故事"

---

## 一、项目一句话介绍

基于正点原子 i.MX6ULL(Cortex-A7 单核)开发板的嵌入式 Linux Qt 应用,包含轮播图、OpenCV 图像处理、摄像头人脸识别、板级设备(LED/蜂鸣器/传感器)、音视频播放和自研 MQTT 客户端 7 个模块;本机 x86 验证 + Ubuntu 交叉编译 + SD 卡部署上板。

---

## 二、3 分钟项目介绍稿(项目部分)

1. **背景**:为了系统学习嵌入式 Linux Qt 开发,参考正点原子例程逐模块复刻并重写,不复制原文件。
2. **架构**:主窗口 = 顶部导航 + `QStackedWidget` 页面堆栈;7 个页面用工厂模式延迟创建,启动只建主框架,点开才实例化页面。
3. **模块**:UI 层(轮播图、音视频播放)、算法层(OpenCV 工具集、Haar 人脸检测)、硬件层(LED/AP3216C/ICM20608,路径可注入)、网络层(自研 MQTT 3.1.1)。
4. **工程质量**:硬件路径注入便于测试;QtTest 自动化测试 22 个用例,`offscreen` 无头运行;Windows 本机 MSVC + 交叉编译两套构建。
5. **成果**:全模块在本机 x86 编译运行通过,自动化测试全绿,完成交叉编译与 SD 卡上板部署流程。

## 四、模块原理速记(一行原理)

| 模块 | 一句话原理 |
|---|---|
| 轮播图 | QTimer 定时 + QPropertyAnimation 位移动画 + 按钮组圆点,5 张图在 qrc 资源里 |
| OpenCV 工具集 | 加载图片后调用 OpenCV 算法(灰度/直方图均衡/滤波/Canny/分割/ORB 等),结果转 QImage 显示 |
| 人脸识别 | OpenCV VideoCapture 取帧 → Haar 级联检测 → 矩形框标注 → QLabel 显示 |
| LED/蜂鸣器 | 向 sysfs 的 brightness 文件写 "1"/"0" |
| AP3216C | 读 `/sys/class/misc/ap3216c` 下的 als/ps/ir 三个节点,定时轮询 + 实时曲线 |
| ICM20608 | 从 `/dev/icm20608` 一次读 7 个 int(六轴+温度),换算后显示 |
| 音乐播放 | QMediaPlayer + QMediaPlaylist 扫描 exe 同目录 myMusic 下的 mp3/flac/wav |
| 视频播放 | QMediaPlayer + QVideoWidget 扫描 myVideo 下的 mp4/mkv/wmv/avi |
| MQTT | 自研协议解析:TCP 收流 → 解析 MQTT 固定头/可变头/载荷 → 发布/订阅 QoS0 |

## 五、高频面试题与回答要点

### 5.1 项目介绍类

**Q: 介绍一下你这个项目?**
回答要点:先说背景和目的(学习嵌入式 Qt),再说架构(导航+堆栈+工厂),再按模块讲功能,最后讲工程化(测试、双平台构建、上板部署)。控制在 2~3 分钟。

**Q: 这是你自己写的吗?参考了哪些东西?**
回答要点:诚实说明是"参考正点原子例程的复刻重写",重点强调自己理解的原理、自己加的改动(工厂模式、路径注入、自研 MQTT、自动化测试、UI 重设计)。

**Q: 项目的难点是什么?**
回答要点:可选 3 个:
1. 交叉编译环境搭建(Qt/OpenCV 都要 ARM 版,库路径和动态库部署);
2. 自研 MQTT 协议解析(按字节解析报文、处理粘包);
3. Windows 播放器问题(系统 Media Foundation 解码器注册损坏,见第六节踩坑故事)。

### 5.2 嵌入式 Linux / 交叉编译

**Q: 什么是交叉编译?为什么用 arm-linux-gnueabihf-gcc?**
回答要点:在 x86 主机上编译出 ARM 架构可执行文件;板子性能弱、没有编译器;工具链前缀决定目标架构(arm、eabi、hf=硬浮点)。

**Q: 交叉编译这个 Qt 工程需要什么?**
回答要点:交叉工具链 + ARM 版 Qt(qmake 指向 ARM mkspec)+ ARM 版 OpenCV 3.4.x;`qmake ARM_OPENCV_DIR=... project.pro`,再 `make`;`file project` 确认 ELF 32-bit ARM。

**Q: 程序怎么部署到板子?**
回答要点:编译出二进制 → 拷到 SD 卡 rootfs 或 NFS/网络 → 把 Qt 库、OpenCV .so、myMusic/myVideo/opencv_src 放到对应目录 → `export LD_LIBRARY_PATH` → `./project -platform eglfs`。

**Q: eglfs 和 linuxfb 区别?**
回答要点:eglfs 走 GPU/EGL,性能好、适合全屏单窗口;linuxfb 直接写 framebuffer,兼容性好但性能弱;黑屏/报错时切换 linuxfb 排查。

**Q: 为什么程序运行时报 "cannot open shared object file"?**
回答要点:动态库没找到;用 `LD_LIBRARY_PATH` 或 `ldd` 检查依赖,把 .so 拷到板子 /usr/lib。

### 5.3 Qt 框架

**Q: 为什么用 QListWidget + QStackedWidget,不用 QTabWidget?**
回答要点:布局更自由(顶部导航可自定义样式)、页面与导航解耦、便于工厂模式延迟创建;QTabWidget 标签页创建更重。

**Q: 工厂模式怎么实现的?好处?**
回答要点:结构体 `PageDescriptor { 标题, 工厂函数指针 }`,注册时只存 lambda,点选页面才 `new`;好处是启动快、内存省、加模块只加一行。

**Q: Qt 信号槽原理?**
回答要点:编译期由 moc 生成代码,connect 把信号与槽关联,事件循环里发射信号调用槽;支持函数指针、lambda、不同写法;注意 lambda 捕获 this 的生命周期。

**Q: Qt 内存管理?**
回答要点:QObject 父子树,`new QPushButton(this)` 父对象销毁时自动 delete 子对象;局部 new 且无父的要手动管理。

**Q: QSS 是怎么工作的?**
回答要点:类选择器/对象名选择器(`#objectName`)/属性选择器,优先级与层叠,`setStyleSheet` 会重绘;全局样式在 main.cpp 加载 qrc 里的 qss。

**Q: QMediaPlayer 播放原理?**
回答要点:Qt 通过插件后端:Linux 用 GStreamer,Windows 用 WMF/DirectShow;播放器只是封装,解码依赖系统后端。

### 5.4 OpenCV / 图像处理

**Q: Canny 边缘检测流程?**
回答要点:高斯去噪 → Sobel 算梯度幅值/方向 → 非极大值抑制 → 双阈值 → 滞后连接。

**Q: 直方图均衡化原理?**
回答要点:把灰度分布拉伸到均匀,增强对比度;对光照不均的图有效。

**Q: Haar 人脸检测原理?为什么慢?**
回答要点:Haar 特征(矩形特征)+ 积分图加速 + AdaBoost 级联分类器;慢是因为多尺度滑窗;加速:缩小图、限制 ROI、多线程、降低 scaleFactor。

**Q: VideoCapture 打不开摄像头怎么排查?**
回答要点:确认 `/dev/video0` 存在、驱动加载、权限、USB 连接;Windows 上设备号从 0 开始。

### 5.5 硬件与驱动

**Q: sysfs 控制 LED 的流程?**
回答要点:内核 LED 驱动注册到 `/sys/class/leds/`,用户态往 brightness 文件写 0/1;本质是 open/write 系统调用。

**Q: sysfs 和 /dev 区别?**
回答要点:sysfs 面向属性(状态、配置),适合简单控制/读取;/dev 面向数据流,适合块/字符设备(如读 7 个 int)。所以 LED 用 sysfs,ICM20608 用 /dev。

**Q: 传感器读不到怎么排查?**
回答要点:先看设备节点是否存在(`ls /sys/class/misc/ap3216c`、`ls -l /dev/icm20608`),再看权限(通常 root),再确认驱动是否加载(dmesg)、I2C 地址是否正确。

**Q: 为什么硬件路径可注入?**
回答要点:构造函数传路径,本机测试传不存在的路径验证容错;板端传真实路径;便于 QtTest 无硬件测试。

### 5.6 MQTT / 网络

**Q: 为什么自研 MQTT?**
回答要点:学习协议本质、减少第三方依赖、可控可调试。

**Q: MQTT 报文结构?**
回答要点:固定头(类型+标志+剩余长度)、可变头(按报文类型)、载荷;剩余长度用变长编码。

**Q: QoS 0/1/2?你实现的是哪个?**
回答要点:QoS0 最多一次(不确认)、QoS1 至少一次( PUBACK)、QoS2 恰好一次(四步握手);当前实现 QoS0,升级 QoS1 需加报文 ID、重发与确认状态机。

**Q: TCP 粘包怎么处理?**
回答要点:按剩余长度字段解析完整报文,缓冲区累积,不足继续等。

### 5.7 测试与工程实践

**Q: 自动化测试怎么做到无头运行?**
回答要点:`QT_QPA_PLATFORM=offscreen` 让 Qt 用离屏平台,不弹窗口,可跑在 CI/无显示环境。

**Q: 硬件代码怎么测?**
回答要点:路径注入 + 构造不存在路径/不可写文件,验证"设备不存在"等容错分支;纯换算逻辑(ICM20608 原始值→物理值)单独测。

**Q: 测试用例测了什么?**
回答要点:主框架(7 个页面、导航切换、UI 对象名/图标资源)、硬件层(LED 读写、传感器容错、数据换算);共 22 个用例。

### 5.8 性能与适配

**Q: imx6ull 性能弱,你怎么优化?**
回答要点:页面延迟创建;OpenCV 重操作放子线程(QThread/线程池),避免阻塞 UI;降低轮询/曲线刷新频率;资源压缩;避免大图实时缩放。

**Q: 界面适配到 800×480 怎么做?**
回答要点:布局用伸缩因子和间距而不是写死坐标;大数字/卡片尺寸按屏幕比例;必要时 QScrollArea;字体大小做分级。

### 5.9 开放题

**Q: 项目有什么可改进的?**
回答要点:播放/OpenCV 处理线程化、MQTT 升级 QoS1、增加断线重连、资源用外部文件系统、开机自启(systemd/rcS)、国际化、电量/温度监控。

**Q: 换一块板子要改什么?**
回答要点:交叉工具链与 Qt/OpenCV 库、设备树/内核、硬件节点路径(/sys、/dev)、屏幕分辨率、显示平台(eglfs/linuxfb)。

## 六、踩坑故事模板(强烈建议背熟)

**题目:你在项目中遇到最难的问题是什么?**

1. **现象**:Windows 上 mp3、mp4 都播不了,点击播放无声音/无画面。
2. **分层排查**:
   - 先排除文件:换成 WAV(纯 PCM)能播 → 不是文件损坏;
   - 再排除路径:ASCII 路径也一样 → 不是中文路径问题;
   - 直接调 Media Foundation:`MFCreateSourceReaderFromURL` 成功,mp4 能读出 H.264 样本 → 源解析正常;
   - `MFTEnumEx` 能枚举到 MP3/AAC/H.264 解码器 → 注册表里有条目;
   - 但 `ActivateObject` 实例化解码器失败,返回 `0x800401F0 (CO_E_CLASSSTRING)` → **解码器 COM 注册残缺,实例化不了**。
3. **根因**:精简版 Windows 镜像把媒体组件注册剥掉了(系统里 `mfmp3srcsnk.dll` 都不存在);WAV 不需要解码器所以能播。
4. **解决**:安装 K-Lite/LAV 解码器包,注册可用解码器后恢复正常;并说明板端 Linux 走 GStreamer 不受影响。
5. **收获**:遇到播放问题按"文件→路径→后端→解码器"分层定位,用最小程序(playcheck/mfcheck)直接调用系统接口拿错误码,而不是瞎猜。

## 七、易被追问的细节清单

- 轮播图为什么用 5 张?答:资源里注册了 1~5.jpg,循环 `1..5`;加图要改 banna.cpp 和 res.qrc。
- 音频支持哪些格式?答:mp3/flac/wav;视频 mp4/mkv/wmv/avi。
- 图片/样式为什么不用拷?答:qrc 编译进 exe(rcc 生成 qrc_res.cpp)。
- 为什么 OpenCV 锁 3.4.x?答:代码用了旧接口 `types_c.h`,4.x 编译不过。
- `myMusic`/`myVideo` 为什么必须和 exe 同目录?答:代码用 `applicationDirPath()` 拼相对路径扫描。
- MQTT 默认连哪?答:127.0.0.1:1883,可用公共 broker 改配置测试。

## 八、上板部署流程速记

```bash
# Ubuntu 交叉编译
./build_arm.sh                      # 自动找 ARM qmake / OpenCV,找不到就传路径

# 部署到 SD 卡 rootfs 分区(先 lsblk 确认设备号!)
sudo ./deploy_sd.sh /dev/sdb /dev/sdb2

# 板子上运行
cd /home/root/project
export QT_QPA_PLATFORM=eglfs       # 黑屏换 linuxfb
export LD_LIBRARY_PATH=/usr/lib:/usr/lib/qt5.6.2/lib:$LD_LIBRARY_PATH
./project
```

## 九、面试避坑提示

3. **准备好"不会"的回答**:不知道就说"这部分我了解不深,我目前的认知是……"。
4. **项目数据要记牢**:22 个测试用例、7 个模块、Qt 5.15.2、OpenCV 3.4.16、1024×600。
5. **上板细节别含糊**:交叉编译、SD 卡部署、LD_LIBRARY_PATH、eglfs 这些流程要能完整讲出来。
